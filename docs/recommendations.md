# Рекомендации по развитию TorrWatch

Документ составлен по итогам технического ревью проекта. Это не обязательный
план, а список идей и приоритетов перед использованием другими людьми.

## Приоритет 1 — сделать в первую очередь

### 1. CI и автоматическая проверка

- Запускать `pytest` в CI.
- Проверять `ruff` и `mypy`.
- Проверять сборку Docker-образа.
- Проверять применение Alembic-миграций.
- Добавить минимальный smoke-тест запуска web и worker.

### 2. Усилить вход администратора

- Увеличить минимальную длину пароля до 12 символов или добавить проверку сложности.
- Ограничить количество попыток входа.
- Добавить временную блокировку после серии неудачных попыток.
- Предупреждать при работе без HTTPS.
- В будущем добавить несколько администраторов и роли.

### 3. Проверять восстановление из backup

Регулярно проверять полный сценарий:

1. Создать backup.
2. Развернуть чистый экземпляр.
3. Восстановить SQLite, артефакты и `master.key`.
4. Проверить расшифровку Cookie, паролей и настроек.

### 4. Исправить отображение времени в диагностическом журнале

Сейчас технические логи используют UTC, а интерфейс — выбранный часовой пояс.
Нужно явно показывать в журнале `UTC` либо переводить timestamps в настройку
часового пояса пользователя.

### 5. Улучшить контроль worker

Показывать:

- время последнего запуска;
- время последней остановки;
- причину последней остановки;
- количество перезапусков;
- задачи, восстановленные после остановки.

## Приоритет 2 — удобство для новых пользователей

- Добавить мастер первого запуска.
- Проверять права на каталог `/data`.
- Сделать пошаговую проверку подключения к клиенту и трекеру.
- Явно объяснить, что Cookie может истекать и требует повторного импорта.
- Сделать отдельную страницу диагностики с готовыми рекомендациями.
- Добавить экспорт диагностического отчёта одним архивом.

## Плагины и новые трекеры

Для будущих сторонних плагинов желательно добавить:

- пакетный формат плагина;
- версию API и проверку совместимости;
- явное включение администратором;
- доверенный список или подпись плагинов;
- шаблон нового плагина и подробную документацию.

Произвольный Python-код из `/data/plugins` нельзя считать безопасным sandbox-ом.
FlareSolverr лучше добавлять как необязательный адаптер для отдельных трекеров,
а не как обязательную часть ядра.

## Приоритет 3 — эксплуатация

- Автоматически очищать старые логи, события и torrent-артефакты.
- Добавить пагинацию для событий и очередей.
- Ограничить размер журнала в интерфейсе.
- Добавить тесты зависших задач и истёкших Cookie.
- Подготовить безопасный пример reverse proxy с HTTPS.
- По умолчанию публиковать web-порт только на `127.0.0.1`, если внешний доступ
  не нужен.
- Проверять backup/restore в CI или отдельной nightly-задачей.

## Рекомендуемый ближайший порядок

1. CI.
2. Backup/restore-тест.
3. Ограничение попыток входа и усиление пароля.
4. Улучшение статуса и перезапусков worker.
5. Исправление часового пояса в диагностическом журнале.
6. Мастер первого запуска и улучшение диагностики.
