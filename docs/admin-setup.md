# Первичная настройка через браузер

Это исправление интерфейса v1, не новая фаза разработки. После входа обзор
показывает шаги настройки, счётчики подключений и последний heartbeat worker.
Локальные CSS и JavaScript работают без CDN и Node.

1. **Торрент-клиенты → Добавить** (`/configure/clients`): выберите qBittorrent
   или Transmission, укажите URL Web API и учётные данные. LAN-адрес разрешён.
   Каталог относится к файловой системе клиента, не NAS-контейнера TorrWatch.
2. **Трекеры и сессии → Импортировать** (`/configure/sessions`): выберите
   трекер и либо вставьте значение заголовка Cookie из запроса страницы раздачи
   вместе с соответствующим User-Agent, либо нажмите **Создать код для
   расширения**. В расширении TorrWatch Session Import откройте нужный трекер,
   вставьте одноразовый код и подтвердите передачу. Код действует 5 минут и
   используется один раз. Не передавайте cookie в чат.
   Сохранённые cookie не отображаются; импорт не доказывает действительность
   авторизации — её проверяет worker при следующей проверке раздачи.
3. **Пути хранения → Добавить** (`/configure/paths`): задайте понятное имя и
   абсолютный путь на стороне торрент-клиента (например, `Сериалы` →
   `/volume1/Download/complete/Serials`). Затем в **Торренты → Добавить**
   укажите URL конкретной раздачи и интервал от 300 секунд; выберите клиент,
   путь и при необходимости прокси. Название торрента вводить не нужно — после
   первой проверки оно автоматически берётся из заголовка страницы.
   Cookie нужного трекера подставляется автоматически.
   После изменения URL интерфейс показывает трекер, канонический адрес и ID
   без сетевого обращения к трекеру.
4. **Проверить сейчас** на странице торрента ставит durable job в очередь.
   Повторный клик не создаёт вторую активную проверку. Для мониторов, созданных
   через интерфейс, первый успех создаёт baseline и сразу доставляет текущий
   validated torrent в выбранный клиент. Дальше доставляются только новые
   authoritative infohash. Результат доступен в истории торрента.
5. Необязательно: **Уведомления → Добавить**, Telegram (Bot token, Chat ID)
   или webhook (URL, Authorization, JSON-заголовки). **Отправить тест** создаёт
   работу в существующей notification queue; результат показан в истории отправок.

## Редактирование и безопасность

Пароли, cookie и конфигурация уведомлений доступны только для записи.
Пустой секрет при редактировании сохраняет прежнее значение. После ошибки
валидации несекретные поля остаются заполненными, секрет нужно ввести снова.
Изменение типа уведомления требует конфигурации нового типа.
Смена URL существующего торрента запрещена: создайте другой торрент, чтобы
не смешать историю разных раздач. Пауза останавливает расписание, но уже
выполняющаяся проверка может завершиться.

UI использует существующий namespace `<plugin>:account:1` для одной общей
сессии каждого трекера. Сессии разных плагинов не смешиваются.

Прокси по умолчанию fail-closed (`DISABLED`). `DIRECT` — явное разрешение
прямого подключения при отказе. `PROFILE` сохраняет ранее настроенную цепочку;
создание цепочек через форму не поддерживается.

На странице **Система / настройки** можно включить безопасный режим отладки:
подробные события доступны для копирования через «Скачать журнал событий», но
секреты и cookies проходят через redaction. Вход без пароля ограничен запросами
с localhost; для доступа по сети пароль остаётся обязательным. Флажок
«Запомнить меня» продлевает сессию до 30 дней (обычная сессия — 12 часов).

## Ограничения интерфейса

- **Проверить подключение** на странице клиентов ставит проверку в очередь.
  Результат доступен в **Очереди** (`/queues`); запрос страницы не обращается к клиенту.
- Импорт cookie ручной; автоматического входа, CAPTCHA обхода и поиска нет.
- Состояния фоновых работ обновляются при обновлении страницы, без live push.
- Создание и редактирование подключений доступны через browser forms.
- Публичного REST API и API-токенов нет.

## Ежедневное управление

Верхний индикатор на каждой странице показывает состояние worker и количество
раздач или доставок, требующих внимания. Страница **Торренты** показывает
последнюю/следующую проверку, выбранный клиент и состояние доставки. В карточке
торрента доступны текущий релиз, размер, hashes, последние события и прямое
действие для типовой ошибки. **Фоновые операции** используют понятные названия,
а **События** фильтруются по торренту, уровню и тексту.

`/system` показывает готовность web, возраст heartbeat, версию схемы и
очереди из SQLite. Отсутствующий heartbeat не выдаётся за здоровый worker.

## Проверка release fix

### Административные действия

- Сессия: «Не настроена», «Ожидает проверки», «Проверяется», «Работает» или
  «Истекла или неверная Cookie». Импорт не подтверждает авторизацию. Сетевые
  ошибки не меняют её на истёкшую; новая Cookie сбрасывает старый результат.
- **Очереди** показывает проверки, операции клиентов, доставки и уведомления.
  Неудачную доставку можно повторить после исправления настроек; активная
  задача не дублируется. Для удалённых торрентов повтор запрещён.
- **Удалить** открывает подтверждение. По умолчанию клиент не затрагивается.
  Флажок дополнительно ставит удаление текущего infohash в очередь клиента,
  всегда без удаления скачанных файлов. Старые версии и другие раздачи клиента
  не удаляются. При выполняющейся проверке/доставке дождитесь её окончания.
  Неудавшееся удаление видно в очереди; временные ошибки повторяются до 5 попыток.
- История и локальные torrent-артефакты сохраняются. Ожидающие проверки и
  доставки удаляемой темы отменяются. При смене адреса клиента после
  подтверждения удаление прекращается, чтобы не затронуть другой сервер.
