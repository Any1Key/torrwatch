# TorrWatch

Самостоятельно размещаемый сервис для мониторинга конкретных раздач на торрент-трекерах.

TorrWatch периодически проверяет страницы раздач, обнаруживает новые версии torrent-файлов, сохраняет историю изменений, передаёт обновления в Transmission или qBittorrent и отправляет уведомления в Telegram.

Проект предназначен для домашнего сервера, NAS или небольшого локального сервера. Он не выполняет поиск по трекерам и не является каталогом раздач: каждый монитор добавляется явно по URL конкретной страницы.

## Возможности

- мониторинг конкретных раздач по расписанию;
- плагины трекеров и проверка страниц раздач;
- история версий и событий;
- доставка обновлений в Transmission или qBittorrent;
- фоновые очереди проверок, доставки и уведомлений;
- Telegram и HTTP(S)-webhook уведомления;
- автоматическое обновление сессий NNM-Club и Kinozal через FlareSolverr;
- зашифрованное хранение паролей, токенов и технических сессий;
- встроенная справка, диагностика и журналы.

## Архитектура

```text
┌──────────────────────┐
│      torrwatch-web   │  интерфейс, настройки, журналы
└──────────┬───────────┘
           │ SQLite /data
┌──────────▼───────────┐
│    torrwatch-worker  │  проверки, доставка, уведомления
└──────┬─────────┬─────┘
       │         ├──────────► Transmission / qBittorrent
       │         ├──────────► Telegram / webhook
       │         └──────────► FlareSolverr
       └────────────────────► торрент-трекеры
```

`web` принимает настройки и ставит операции в очередь. `worker` забирает задания, проверяет трекеры, обновляет сессии, сохраняет версии, доставляет торренты и отправляет уведомления. FlareSolverr используется для автоматического открытия защищённых страниц NNM-Club и Kinozal.

## Установка через Docker Compose

### Требования

- Docker Engine;
- Docker Compose v2;
- свободный порт `8080`;
- сетевой доступ к торрент-клиенту и нужным трекерам.

### Запуск

```bash
git clone https://github.com/Any1Key/torrwatch.git
cd torrwatch
cp .env.example .env
```

Compose использует готовый образ с Docker Hub:

```text
ruslanchikt/torrwatch:latest
```

Для предсказуемого обновления можно указать конкретную версию в `.env`:

```dotenv
TORRWATCH_IMAGE=ruslanchikt/torrwatch:0.1.0
```

Измените в `.env` как минимум:

```dotenv
TORRWATCH_ADMIN_USERNAME=admin
TORRWATCH_ADMIN_PASSWORD=замените-на-длинный-пароль
```

Запустите сервисы:

```bash
docker compose pull
docker compose up -d
docker compose ps
```

После запуска интерфейс доступен локально по адресу:

```text
http://localhost:8080/
```

При открытии с другого компьютера используйте IP-адрес NAS или сервера, на котором запущен TorrWatch, например `http://SERVER_IP:8080/`. Проверка готовности на самом сервере:

```bash
curl http://127.0.0.1:8080/health/ready
```

Ожидаемый ответ: `{"status":"ready"}`.

Остановка:

```bash
docker compose down
```

Обновление до последней версии:

```bash
docker compose pull
docker compose up -d
```

Для локальной разработки и сборки из исходников используйте dev-override:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

Не добавляйте `.env` в Git: в нём могут находиться пароли и токены.

## Первоначальная настройка

1. Откройте **Подключения → Торрент-клиенты**.
2. Добавьте Transmission или qBittorrent и проверьте подключение.
3. Откройте **Подключения → Трекеры**.
4. Выберите трекер в списке и настройте его логин и пароль.
5. Для NNM-Club и Kinozal проверьте URL FlareSolverr в разделе **Интеграции**.
6. Откройте **Торренты → Добавить монитор**.
7. Вставьте URL страницы конкретной раздачи.
8. Выберите интервал, торрент-клиент и путь сохранения.
9. Нажмите **Проверить сейчас** или дождитесь плановой проверки.

Для NNM-Club и Kinozal ручная передача Cookie, User-Agent и браузерное расширение не требуются. Worker сам обновляет техническую сессию через FlareSolverr.

Kinozal поддерживает ссылки с доменов `kinozal.tv`, `kinozal.guru` и `kinozal.me`.

## Как работает мониторинг

1. Worker получает задание проверки из очереди.
2. Плагин открывает страницу трекера и извлекает torrent-файл.
3. TorrWatch проверяет структуру файла и определяет его идентичность.
4. Первая успешная проверка создаёт baseline-версию.
5. При изменении torrent-идентичности новая версия сохраняется в истории.
6. Новая версия ставится в очередь доставки, если выбран торрент-клиент.
7. После проверки нового торрента старая задача клиента может быть удалена без удаления скачанных данных.
8. Событие записывается в журнал и при необходимости отправляется в Telegram или webhook.

Кнопка **Проверить сейчас** только ставит задачу в очередь. Сетевой запрос выполняет worker, поэтому результат может появиться через несколько секунд.

## Уведомления

Поддерживаются следующие типы Telegram-уведомлений:

- обновление раздачи;
- успешная доставка в торрент-клиент;
- ошибка доставки;
- ошибка авторизации трекера;
- ошибка трекера или Cloudflare;
- недоступность торрент-клиента;
- системная ошибка.

Сообщение может содержать название раздачи, ID трекера, размер, количество файлов, клиент, путь, описание события и время. Кнопок внутри сообщений нет.

Для Telegram нужны Bot Token и Chat ID. Для личного чата сначала отправьте боту `/start`. После сохранения канала можно отправить тестовое уведомление.

## Очереди и состояния

Отдельно обрабатываются:

- проверки страниц трекеров;
- доставка torrent-файлов;
- Telegram и webhook уведомления;
- административные операции клиентов;
- обновление сессий через FlareSolverr.

| Состояние | Значение |
|---|---|
| `PENDING` | ожидает worker |
| `RUNNING` | выполняется |
| `SUCCESS` | завершено успешно |
| `FAILED_RETRYABLE` | временная ошибка, будет повтор |
| `FAILED_PERMANENT` | требуется исправить настройки и повторить вручную |

Раздел **Очереди** показывает задержанные, выполняющиеся и ошибочные операции.

## Безопасность и данные

Постоянные данные находятся в `./data`:

- SQLite-база;
- torrent-файлы и история версий;
- журналы;
- ключ шифрования `master.key`.

Секретные значения хранятся зашифрованными. Ключ нужен для восстановления паролей, токенов и сессий, поэтому его необходимо включать в защищённую резервную копию.

Никогда не публикуйте `.env`, `data/master.key`, Telegram Bot Token, пароли, Cookie и содержимое диагностических дампов.

FlareSolverr настроен с уровнем логирования `error`, потому что подробные HTTP-запросы могут содержать секреты сессии.

## Резервное копирование

```bash
docker compose exec web torrwatch backup /data/backup
```

По умолчанию команда не включает ключ шифрования. Для полного защищённого резервного копирования используйте `--include-master-key` и храните архив отдельно от Git-репозитория.

Перед восстановлением остановите `web` и `worker`, чтобы база не изменялась во время копирования.

Для регулярного обслуживания можно использовать:

```bash
TORRWATCH_BACKUP_KEEP=7 ./scripts/maintenance.sh
```

Скрипт создаёт резервную копию, удаляет только старые каталоги с префиксом `backup-` и очищает неиспользуемые Docker-образы с меткой TorrWatch. Запуск удобно добавить в планировщик NAS или cron.

## Диагностика

```bash
docker compose ps
docker compose logs -f web
docker compose logs -f worker
docker compose logs -f flaresolverr
docker compose exec web torrwatch doctor
docker compose exec web torrwatch plugins list
```

Если монитор не обновляется, проверьте worker, очередь, логин и пароль трекера, доступность FlareSolverr, торрент-клиент и журнал конкретной раздачи.

Журналы приложения ротируются автоматически: размер одного файла ограничен 5 МБ, сохраняются три резервных файла. Подробное логирование следует включать только на время диагностики.

## Разработка

Проект использует Python 3.12 и `uv`:

```bash
uv sync
python -m compileall torrwatch
uv run ruff check torrwatch
uv run pytest
```

### Публикация образа

Основной образ публикуется в Docker Hub как `ruslanchikt/torrwatch`. Для
ручной публикации локальной сборки:

```bash
docker build -t ruslanchikt/torrwatch:latest .
docker login -u ruslanchikt
docker push ruslanchikt/torrwatch:latest
```

GitHub Actions публикует образ автоматически после push в `main` и при создании
тега вида `v0.2.0`. Для workflow нужно добавить в настройках репозитория secret
`DOCKERHUB_TOKEN` — Personal Access Token Docker Hub с правом чтения и записи.

Локальные команды приложения:

```bash
uv run torrwatch-web
uv run torrwatch-worker
```

## Ограничения

- мониторинг работает только для явно добавленных страниц;
- поиск по трекерам и массовый сбор каталога не выполняются;
- проверки и доставка асинхронные и зависят от worker;
- первая найденная версия создаёт baseline и не считается обновлением;
- автоматическая сессия через FlareSolverr зависит от корректных учётных данных NNM-Club или Kinozal;
- доступность закрытых трекеров зависит от авторизации, Cloudflare и сети.
