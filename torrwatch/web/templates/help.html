Быстрый старт

  1. Подключите торрент-клиент в разделе «Подключения → Торрент-клиенты».
  2. Откройте нужный трекер в браузере и войдите в аккаунт.
  3. Импортируйте Cookie через «Интеграции → Обзор интеграций» и браузерное расширение.
  4. Добавьте URL конкретной раздачи в разделе «Торренты».
  5. При необходимости выберите клиент и путь сохранения.
  6. Откройте страницу раздачи и убедитесь, что первая проверка завершилась успешно.

Трекеры и Cookie

TorrWatch открывает страницы трекера от имени вашей браузерной сессии. Для NNM-Club расширение передаёт необходимые Cookie и User-Agent.

Если появляется ошибка авторизации или Cloudflare challenge:

  • зайдите на трекер в браузере;
  • обновите страницу;
  • создайте новый pairing token;
  • передайте сессию расширением заново;
  • запустите проверку раздачи вручную.

Секретные значения хранятся зашифрованными. Не отправляйте Cookie и токен бота в переписку.

Торрент-клиент

Поддерживаются Transmission и qBittorrent. В настройках указываются URL Web API, логин, пароль, путь сохранения, категория и теги.

Кнопка «Проверить подключение» создаёт фоновую задачу. Результат смотрите в «Журнал → Фоновые операции».

Путь должен быть понятен самому торрент-клиенту. Это может быть путь внутри NAS, а не путь из браузера или контейнера TorrWatch.

Добавление и проверка раздачи

Указывайте URL конкретной раздачи, а не главную страницу трекера или URL поиска. После сохранения первая проверка ставится сразу.

Интервал
По умолчанию 30 минут, минимально 5 минут.
Проверить сейчас
Принудительно ставит проверку на ближайшее выполнение, даже если ранее была отложенная повторная попытка.
Пауза
Останавливает автоматические проверки до возобновления.

Очереди и фоновые операции

Операции выполняются worker в фоне, поэтому веб-интерфейс не зависает на сетевых запросах.

  • Проверки — открытие страницы трекера и получение состояния раздачи.
  • Доставка — добавление новой версии в Transmission/qBittorrent и удаление старой.
  • Операции клиента — проверка подключения и удаление задачи из клиента.
  • Уведомления — отправка сообщений в Telegram или Webhook.

Статус FAILED_RETRYABLE означает автоматический повтор. FAILED_PERMANENT требует исправить настройки и повторить действие вручную.

Уведомления

В разделе «Интеграции → Уведомления» можно настроить Telegram или Webhook, выбрать типы событий и отправить тест.

Для Telegram нужны Bot Token и Chat ID. Для личного чата Chat ID обычно совпадает с вашим Telegram ID. Сначала откройте диалог с ботом и отправьте ему /start.

Историю отправок смотрите в «Журнал → Фоновые операции».

Если что-то не работает

  • Проверьте верхний индикатор Worker и страницу «Система и настройки».
  • Откройте «Журнал → Фоновые операции» и посмотрите последнюю ошибку.
  • Для ошибки Cookie импортируйте свежую сессию и повторите проверку.
  • Для ошибки клиента проверьте URL, логин, пароль и доступность Web API.
  • Для ошибки Telegram проверьте, что Bot Token и Chat ID не перепутаны.
  • Для повторяющейся ошибки трекера проверьте доступность сайта, прокси и актуальность Cookie.
